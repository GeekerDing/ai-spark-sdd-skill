# SDD 开发就绪质量门禁

## 判定状态

- **Ready**：所有关键输入、输出、业务规则、验收与首个开发任务清楚，可开始开发。
- **Conditionally Ready**：存在已标注的非阻断假设；可用模拟/授权样本开始，但未确认点不得用于生产。
- **Blocked**：缺失的业务规则或必要数据使首次闭环无法定义，或存在尚未解决的严重安全/权限风险。

## 检查清单

- [ ] 用户、场景和业务痛点足够具体，不只有技术愿望。
- [ ] MVP 只有一个主要业务闭环，输入、处理、输出、人工检查环节明确。
- [ ] 所有 Must Have 均在 `spec.md` 中有 `FR-xxx`。
- [ ] 各核心 `FR-xxx` 均关联客观可核验的 `AC-xxx`。
- [ ] `plan.md` 说明如何实现全部 Must Have，并解释关键选型理由。
- [ ] `tasks.md` 包含第一条可执行任务及独立的完成条件。
- [ ] `tasks.md` 的任务关联功能需求，且覆盖示例数据、运行方式和基本测试。
- [ ] 核心业务规则的异常情形已定义。
- [ ] 敏感数据、权限、第三方服务限制已处理或显式标注。
- [ ] 已确认、待确认、假设三类信息清晰区分。
- [ ] 参与者理解第一次 Demo 要展示什么，不需要阅读全部架构图才能开工。

## 反馈格式

```text
开发就绪状态：Ready / Conditionally Ready / Blocked
原因：<一句话>
阻断项：<如无，写“无”>
非阻断假设：<如无，写“无”>
第一项任务：T001 <具体任务>
首个演示：<示例输入 → 处理 → 可检查输出>
建议下一步：<一个可执行动作>
```

若文档内部自相矛盾，优先修改文档再宣布 Ready；不能仅靠“后续再看”跳过检查。

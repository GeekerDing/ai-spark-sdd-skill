# 示例：财务报销明细自动汇总（纯演示，非真实项目）

> 目的：展示如何从口语化痛点进入一个最小 SDD，而不是提供可直接用于生产的会计处理逻辑。

## 用户的最初描述

“每个月要从几个 Excel 里汇总员工报销，经常复制错，希望 AI 帮我自动做。”

## 导师的四个问题

1. 每个月谁来汇总报销？是为哪个后续流程准备数据？
2. 现在通常收集哪些 Excel，哪一步最耗时或容易错？
3. 第一版只处理一种格式的 Excel，生成一份统一明细和总额，是否足够？可以给一组脱敏样本吗？
4. 你目前是否会用 Excel 公式、脚本或 AI Coding 工具？

## 假设收到的回答（仅用于示范）

- 1 位财务同事处理；每个月约 10 份结构相同的 Excel。
- 需要合并日期、员工、金额、费用类型，去除完全重复的记录。
- 第一版只处理 `.xlsx` 文件，不与 ERP 连接。
- 用户没有编程经验；可以提供脱敏样本。

## 业务闭环

多份 `.xlsx` → 校验字段 → 合并和按**约定的唯一键**查重 → 输出汇总 `.xlsx` → 财务人工对照总额。

> 注意：真实项目中“重复”的判定方式必须由财务业务人员确认；这里不得擅自把“相同金额”定义为重复。

## MVP 的 Must / Later / Out

- **Must**：读取约定格式、报错提示缺少字段、导出统一明细、输出合计。
- **Later**：多种报销模板自动识别、图表、部门审批。
- **Out**：自动付款、连接生产 ERP、收集个人隐私资料。

## 可验收的具体例子

- FR-001：用户提交至少 1 份符合模板的 XLSX，系统合并行并生成结果文件。
- AC-001：对于含 3 条金额 `100, 50, 20` 的单文件样本，合计金额为 `170`；输出包含约定的列。
- AC-002：对缺少“金额”列的输入文件，系统不给出看似成功的报告，而是明确提示缺失列。

## 推荐第一条开发任务

T001：建立 Python 本地环境与读取指定 Excel 的最小程序；准备一份只有 3 条数据的脱敏样本；运行后显示读取的行数。此阶段不引入云服务或数据库。

## 提示

此案例中 `AC-001` 的 170 是**人为指定的测试样本预期值**，不是对真实财务数据的声明。实际验收还需考虑金额精度、币种、日期和业务唯一键。
